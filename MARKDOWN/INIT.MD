# Правила введения проекта

Документ для разработчиков и ИИ-агентов. Соблюдать при любых изменениях кода и документации.

Краткая пользовательская документация — в `docs/`. Технические разборы и планы — в `MARKDOWN/`.

---

## Документация

### Разделение папок
| Папка | Назначение |
|-------|------------|
| **`MARKDOWN/`** | INIT, ISSUES, развёрнутые планы, реверс-заметки для разработчиков/ИИ |
| **`docs/`** | Краткие гайды для пользователей и ссылок из README |

### Правила .md
- Собственные пояснения / рапорты / глубокие разборы → **`MARKDOWN/`**
- Краткие пользовательские шпаргалки → **`docs/`**
- Не плодить дубликаты; лучше ссылка «подробно ↔ кратко»
- **`MARKDOWN/INIT.MD` и `.cursor/commands/init.md` должны быть байт-в-байт одинаковыми** — править оба (или копировать один в другой) при любом изменении правил

### Актуальные документы
| Файл | Содержание |
|------|------------|
| [`INIT.MD`](INIT.MD) / [`.cursor/commands/init.md`](../.cursor/commands/init.md) | Правила разработки (синхронная копия) |

## Лицензии и активация

- Проект — **открытая (clean-room) GPL-реимплементация** и работает **без** лицензии, ключей
  и активации: никаких серверов, онлайн-проверок или активационных диалогов.
- Любая логика «отсутствия лицензии» (гейты, `Unlicensed*`-окна, диалоги активации,
  ограничение функций по статусу лицензии) в этом порте **запрещена**.
- Модуль `src/license/` — инертный каркас, зеркалящий референс; он всегда отдаёт
  `Valid`/`Free` и **не должен** использоваться как гейт доступа в UI. Если блокирующая
  ветка обнаружится в коде — её нужно удалить, а не «дополнить» проверкой лицензии.
- Не добавлять новые проверки/запросы лицензии. При появлении такого кода — убрать,
  оставив доступ ко всем функциям безусловно.
