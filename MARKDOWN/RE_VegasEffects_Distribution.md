# Разбор дистрибутива SAMPLES/VEGAS_Effects

Инвентаризация и анализ референс-поставки: состав, версии, граф зависимостей,
процессная модель, подсистема плагинов. Данные получены прямым разбором PE
(заголовки, таблицы импорта/экспорта, ресурсы VS_VERSIONINFO) и поиском строк.

Дополняет [`RE_VegasEffects.md`](RE_VegasEffects.md), где разбирается код самого
`VegasEffects.exe`.

## 3. Собственные модули и граф зависимостей

Статические зависимости между модулями FXhome (по таблицам импорта):

```
DSReader.dll                    DirectShow-ридер (ole32/OLEAUT32)
   ^
FXMedia.dll                     медиа-слой, FileDescription "FXMedia.639a079"
   ^
Project.dll                     документ / модель данных        <- 8 зависимых
   ^          ^          ^
Fusion.dll   Marvin.dll  |      3D-частицы     аудио + медиа-кэш
   ^          ^          |
Flux.dll -----+----------+      рендер-движок
   ^
Tannen.dll                      менеджер плагинов, движок biff
   ^
VegasEffects.exe / RenderClient / Server
```

- **`Project.dll` — фундамент**: от него зависят 8 модулей, включая все
  вышележащие слои. Это модель проекта и ассетов.
- **`Tannen.dll` — вершина библиотечного стека**: тянет Flux, Fusion, Marvin и
  Project, потому что плагину нужно отдать и рендер, и звук, и модель.
- **`Widgets.dll`** — листовая UI-библиотека, нужна только `VegasEffects.exe` и
  `VegasEffectsRenderClient.exe`; у серверного процесса UI нет.

### Модули без статических зависимых (грузятся через LoadLibrary)

Проверено поиском их имён как UTF-16-строк внутри модулей-загрузчиков:

| Модуль | Кем грузится | Назначение (по импортам) |
|--------|--------------|--------------------------|
| `FXMediaNv.dll` | `FXMedia.dll` | NVIDIA-бэкенд: `nvcuvid.dll` (NVDEC), `nvEncodeAPI64.dll` (NVENC), `nvcuda`, `cudart64_110` |
| `FXMediaPr.dll` | `FXMedia.dll` | ProRes-бэкенд с ускорением через `OpenCL.dll` |
| `FXMediaQTServer.exe` | `FXMedia.dll` | внепроцессный сервер QuickTime |
| `VegasEffectsOFXSandbox.exe` | `Tannen.dll` | изолированная проверка OFX-плагинов |

`PluginWidgets.dll` (лежит в `Plugins/2D/`) и `VegasEffectsFileIOPlugin.dll` не
упоминаются ни в одном из проверенных модулей — их имена, вероятно, собираются
во время выполнения или они находятся перечислением каталога.

## 4. Процессная модель

| Процесс | Разр. | Подсистема | Размер | Роль |
|---------|-------|-----------|--------|------|
| `VegasEffects.exe` | x64 | GUI | 23.1 МБ | основное приложение |
| `VegasEffectsRenderClient.exe` | x64 | GUI | 22.8 МБ | рендер-клиент, почти полная копия зависимостей главного |
| `VegasEffectsServer.exe` | x64 | **CUI** | 7.4 МБ | рендер-сервер без UI (нет `Widgets.dll`) |
| `VegasEffectsOFXSandbox.exe` | x64 | CUI | 52 КБ | песочница OFX; зависит **только** от `Project.dll` + `Tannen.dll` |
| `FXMediaTranscoder.exe` | x64 | CUI | 270 КБ | транскодер поверх `FXMedia.dll` |
| `FXMediaQTServer.exe` | **x86** | CUI | 273 КБ | сервер QuickTime |
| `BsSndRpt64.exe` | x64 | GUI | 397 КБ | отправка крэш-репортов BugSplat |
| `QtWebEngineProcess.exe` | x64 | GUI | 591 КБ | рендер-процесс Chromium |

**`FXMediaQTServer.exe` — единственный 32-битный модуль в 64-битной поставке.**
QuickTime для Windows существовал только 32-битным, поэтому 64-битное
приложение обязано общаться с ним через отдельный процесс. Импорты минимальные
(VERSION, KERNEL32, USER32, GDI32, ADVAPI32) — QTML грузится динамически.

Это прямо объясняет ветку, разобранную в
[`RE_VegasEffects.md`](RE_VegasEffects.md) §3.2: `FXMediaStartup()` возвращает
`0x2B`, если QuickTime не установлен (диалог «Please install Apple QuickTime»),
и иной код, если не удалось поднять helper-процесс («There was a problem
starting the QuickTime helper process»).

**`VegasEffectsOFXSandbox.exe` весит 52 КБ** при зависимости только от Project и
Tannen — это минимальный внепроцессный пробник: сторонний OFX-плагин грузится и
опрашивается в отдельном процессе, чтобы его падение не уронило редактор.
Отсюда же команда UI «Delete OpenFX Plugins Cache» — результат опроса кэшируется.

## 5. Подсистема плагинов

`Tannen.dll` — единственный менеджер плагинов, и он поддерживает **три** формата.

### 5.1 Родные плагины `.hfpl` / `.hfplx`

Все **321** файла в `Plugins/` — обычные PE-DLL x64 с расширением `.hfpl`
(HitFilm PLugin). Каталоги: `2D` (242), `Behavior` (43), `Audio` (16),
`VideoTransitions` (15), `Geometry` (4), `AudioTransitions` (2).

**ABI предельно узкий.** У всех 321 плагина ровно **два экспорта**:

```
PluginInfo
Notify
```

Ни один не экспортирует ничего другого. Загрузчик в `Tannen.dll` ищет по маскам
`*.hfpl` и `*.hfplx`, при отсутствии символа сообщает «Missing plugin entry
point», при отсутствии каталога — «Directory does not exist: ».

**265 из 321 плагина импортируют `opengl32.dll`** — эффекты считаются на GPU, а
не на CPU. Самые крупные (по 2.2 МБ) — текстовые и трекинговые: `Text`,
`CreditsTextCrawl`, `PulpScifiTitleCrawl`, `AutomaticStabilizer`, `MotionLock`.

#### Блок метаданных: `PluginFile::ReadPluginMetadata`

`biff::tannen::PluginFile::ReadPluginMetadata(BiffHost&, tagBiffAPI&)`
(`Tannen.dll`, `0x18035adb0`) — единственное место, где хост читает описание
плагина. Он вызывает разрешённый экспорт `PluginInfo` косвенно, через указатель
в объекте (`(**(code**)(*this + 0x40))(host, api, &metadata)`), и передаёт третьим
аргументом структуру на стеке, **буферы в которой выделяет сам**:

| Смещение | Что лежит | Размер буфера | Кодировка |
|---------|-----------|--------------|-----------|
| `+0x00` | тип плагина (`int`, 0…5) | — | — |
| `+0x04`…`+0x14` | пять `int`-полей | — | — |
| `+0x18` | отображаемое имя | 1024 Б | UTF-16 |
| `+0x20` | категория | 600 Б | UTF-16 |
| `+0x28` | вендор | 200 Б | UTF-16 |
| `+0x30` | копирайт | 800 Б | UTF-16 |
| `+0x68` | идентификатор | 100 Б | ASCII |

Тип вне диапазона 0…5 приводит к исключению «Invalid plugin type»; шесть
допустимых значений отображаются на внутренний вид (`obj+0x50`) перестановкой
`0→0, 3→1, 1→2, 2→3, 4→4, 5→5` и соответствуют шести подкаталогам `Plugins/`.

**Ключ эффекта.** Идентификатор вида `com.FXHOME.HitFilm.360Blur` режется по
последней точке (таблица символов в функции задаёт единственный разделитель —
`0x2E`), и к хвосту приписывается литерал `Effect_`. Получается `Effect_360Blur`.
Имя файла в этом не участвует: `360LightsaberV2Auto.hfpl` объявляет
`com.FXHOME.HitFilm.360LightswordAuto` и ключуется как `Effect_360LightswordAuto`.

**Категория разбирается как список.** Поле `+0x20` разрезается по `|`
(`U+007C`) и собирается обратно тем же разделителем — то есть плагин может быть
заявлен сразу в нескольких категориях. В поставке этим никто не пользуется:
ни один из 321 файла не содержит `|` в этом поле.

#### Локализация строк плагина

Имя и категория проходят через
`QCoreApplication::translate(context, source)`, где `context` — тот самый ключ
`Effect_<ShortName>`. Копирайт переводится отдельно, с общим контекстом
`PluginStrings`. Вендор не переводится вовсе — это торговая марка.

Это проверяется по каталогам самого референса: в
`Translations/ja/VegasEffects_ja.qm` **ровно 321 контекст `Effect_*`** — столько
же, сколько файлов `.hfpl`, — плюс контекст `PluginStrings`, содержащий одну
строку копирайта. В контексте лежит весь словарь плагина: имя, категория,
подписи параметров, единицы и варианты перечислений. Например
`Effect_360Blur` (10 сообщений):

```
360° Blur | 360° Video | Radius | Dimension | px
Horizontal | Vertical | Horizontal & Vertical
360° 2πᶜ equirectangular equidistant | Blur Radius Changed
```

Всего в `Effect_*` — 6818 сообщений.

#### Что из этого извлекается статически

В самом `.hfpl` это не структура, а пул строк `.rdata`, разложенный в порядке
первого использования, поэтому позиционный разбор работает лишь частично.
Надёжно читаются **идентификатор**, за которым подряд идут **вендор** и
**категория** (UTF-16, выравнивание нулями).

Отображаемое имя лежит не рядом, но восстанавливается точным правилом: ровно
один UTF-16 литерал модуля совпадает с последним сегментом идентификатора после
свёртки (отбросить всё, кроме букв и цифр, привести к нижнему регистру), —
`360Blur` ↔ `360° Blur`. Реализовано в `probeNativePlugin()`; проверено на всех
321 плагине против эталонного каталога:

| Что | Результат |
|-----|-----------|
| идентификатор, категория | 321 / 321 |
| контекст найден в `.qm` | 320 / 321 |
| категория подтверждена | 320, расхождений 0 |
| имя восстановлено | 245, из них подтверждено 244, ошибочных 0 |

Единственный промах — `Effect_Clouds`: этого контекста нет в японском каталоге,
то есть плагин не переведён у самого референса. Для оставшихся 76 плагинов, где
правило не срабатывает (имя содержит то, чего нет в идентификаторе —
`360LightswordAuto` → `360° Lightsword (2-Point Auto)`), порт разбивает
идентификатор на слова.

Подписи параметров таким способом не достаются: в пуле они соседствуют с
ASCII-ключами (`radius`, `dimension`) и вариантами перечислений, но порядок
задаёт компилятор, а не структура. Достоверный источник для них — контекст
`Effect_<ShortName>` в каталоге перевода.


### 5.2 OFX (OpenFX)

В поставке **нет ни одного `.ofx`-файла** — OFX-хост существует для плагинов,
которые ставит пользователь. В `Tannen.dll` найдено **315 символов `Ofx*`**:
полный набор действий (`OfxActionDescribe`, `OfxActionCreateInstance`,
`OfxActionInstanceChanged` и далее), точки входа `OfxGetPlugin` и
`OfxGetNumberOfPlugins`, и — что важно — `OfxActionOpenGLContextAttached` /
`OfxActionOpenGLContextDetached`, то есть поддержан OpenGL-рендер OFX.

Нестандартные расширения формата: глубины `OfxBitDepthByteBGR`,
`OfxBitDepthShortBGR`, `OfxBitDepthFloatBGR` (порядок каналов BGR) и
`OfxBitDepthHalf`.

Собственная сюита задокументирована в поставляемом заголовке
`include/OFX/ofxHitFilmExtensions.h` (604 строки): `OfxHitFilm3DSuite` — камеры
(`OfxTypeHitFilmCamera`: matrix, zoom, FOV, focus distance, aperture, blur
level), источники света (ambient / point / spot / directional — интенсивность,
цвет, конус, тени) и трансформы (`OfxHitFilmProp3DTransformMatrix`). Это мост,
через который OFX-плагин получает доступ к 3D-сцене хоста.

Есть регулярное выражение, выделяющее `BCC_OFX_3D_Objects.ofx`, — для Boris
Continuum сделана отдельная обработка как совместимостный частный случай.

### 5.3 Плагины After Effects

В `Tannen.dll` присутствуют конструкции AE SDK: `AEGP`, `PF_Cmd`, `Adobe`,
строки «Effect does not support Smart Render» и `Effect_Parent_Layer`. Значит
хост умеет грузить и эффекты After Effects. В списке шаблонов поиска рядом с
`*.hfpl` стоит маска `*.80`, что соответствует типу AE-плагинов.

### Alembic (разобрано в Ghidra)

Версию не пишут в ресурсы — она собирается в коде
(`Alembic::AbcCoreAbstract::v12::GetLibraryVersion`, `0x180021920`) потоковым
выводом `1 << "." << 8 << "." << 3`, то есть **1.8.3**; пространство имён `v12`
это подтверждает (Alembic 1.8.x). Импортируется `imath_half_to_float_table` —
библиотека собрана против Imath 3.1 из той же поставки.

Экспортируются схемы и на чтение, и на запись:

- чтение: `IArchive`, `ICameraSchema`, `IPolyMeshSchema`, `IXformSchema`;
- запись: `OArchive`, `OCameraSchema`, `OXformSchema`, `OPolyMeshSchema`,
  `OSubDSchema`, `OPointsSchema`, `ONuPatchSchema`, `OLightSchema`,
  `OFaceSetSchema`.

Наличие `OCameraSchema` вместе с `hdf5.dll` объясняет команду **Export Camera**
из реестра команд (раздел 6 `RE_VegasEffects.md`): камера выгружается в `.abc`
как `OXform` + `OCamera`. Обратная сторона — `ICameraSchema` — даёт импорт
трека камеры из 3D-пакета.

## 7. Данные, конфигурация, локализация

**`qt.conf`** (37 байт) делает поставку самодостаточной:

```
[Paths]
Prefix = .
Translations = .
```

Prefix, указывающий на каталог приложения, отвязывает Qt от системных путей;
`platforms/`, `imageformats/`, `audio/`, `mediaservice/` лежат рядом с exe и
находятся через путь приложения.

**Локализация** — только японский и упрощённый китайский. Для каждого языка:
`VegasEffects_<loc>.qm` (~0.9 МБ), `qt_<loc>.qm` и `AboutLicenseWin.txt`.
Английский зашит в код. Это согласуется с тем, что загрузчик переводов
(`FUN_140267320`) шесть раз обращается к резолверу папок с индексом 0
(`Translations`).

**Chromium**: `icudtl.dat` (10.5 МБ), `qtwebengine_resources.pak` и варианты
`_100p` / `_200p`, локаль `qtwebengine_locales/en-US.pak` — только английская.

**`LICENSE-LGPL-2.1`** в корне — обязательство по LGPL за динамически
слинкованный Qt.

## 9. Что из этого следует для OpenVegas

1. **Расширение плагинов не то.** `PluginManager` в
   [`src/plugin/PluginManager.cpp`](../src/plugin/PluginManager.cpp) ищет файлы
   с суффиксом `vfx`. В референсе таких файлов нет вообще: родные плагины —
   `*.hfpl` и `*.hfplx`. Для совместимости сканировать надо их.
2. **ABI родного плагина крайне прост** — два экспорта, `PluginInfo` и `Notify`.
   Это реалистичная цель для реализации, в отличие от полного OFX-хоста.
3. **OFX — отдельная и большая задача**: 315 символов, включая OpenGL-рендер и
   собственную 3D-сюиту. Заголовок `include/OFX/ofxHitFilmExtensions.h` уже
   лежит в поставке и является готовой спецификацией для 3D-части.
4. **Внепроцессная песочница для плагинов** — решение, которое стоит перенять:

5. **Названия папок данных** в поставке (`Plugins`, `Translations`,
